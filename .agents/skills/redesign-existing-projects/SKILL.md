# Existing-page refinement

Start with the actual page and its current user flow. List concrete visual or interaction problems with route, viewport, and evidence. Rank the smallest corrections that address the request, implement only those, then compare the same states with `visual-qa`. Keep the current information architecture, content, access behavior, and working components unless the task explicitly changes them.

Use [the Li Family visual system](../../../docs/design/li-family-visual-system.md) for shared identity and `shadcn-stack` for component implementation. `design-taste-frontend` may supply a single design read for an explicitly requested redesign, but it is not a second competing direction. Generic audit heuristics cannot require a new font, icon library, dependency, dark mode, texture, animation, or full-page rewrite. Follow `AGENTS.md` for authority.

For a relevant task, search and read only the applicable headings in [the preserved technique reference](references/audit-checklist.md). The reference is not a checklist that must be applied in full.
